# 项目结构整理记录

日期：2026-10-13。目标是明确当前产品入口、学习路线、模块职责和修改源。本轮暂停新增功能，未重新发布桌面 EXE，未覆盖或重启板端正在运行的服务。

## 1. 整理前的问题

- 原 `avctl.py` 混合配置、辅助函数、进程生命周期、Unix socket 服务和命令行解析。
- 原 `window.py` 混合界面构建、业务回调和本地 MP4 回放；大量一行式语句增加阅读成本。
- 根目录和交付副本并列，缺少明确的源码阅读顺序；旧脚本编号容易被当作当前启动流程。
- 操作指南、设计、优化与历史验收并列，没有统一目录；README.txt 仍指向旧 1.0.0 ZIP。

## 2. 代码调整

板端对外保留 `avctl.py`，内部拆成 `camera_control/config.py`、`support.py`、`controller.py`、`transport.py`、`cli.py`。控制服务仍独占生命周期状态，配置根目录保持入口上级目录；Unix socket、systemd 调用、动作名和 JSON 格式保持原有契约。

桌面抽出 `layout.py` 组装界面，`playback.py` 管理本地回放；`window.py` 保留业务编排、状态回调和退出。读取已保存凭据归到业务初始化中。SSH、视频、SFTP 工作线程职责延续已有划分。

Python 源码统一展开语句与缩进，保留原注释。格式化工具仅置于本地验证目录，不加入产品运行依赖或依赖锁定文件。

## 3. 导航和交付调整

- 新增项目程序逻辑文档和三链路架构图，说明连接、启动、预览、录像、下载、参数应用和退出全过程。
- 为 board、FFmpeg、MPP C API、desktop 与 docs 建立各自导航。
- README 改为按目的查入口；方案网页增加项目逻辑入口；修正 README.txt 旧版本号。
- 标明 Markdown 是文档编辑源，HTML 与源码包由工具生成；产品代码、学习代码、运行数据与备份分别解释。
- 文档生成器支持架构图响应式显示，HTML 文档之间自动链接到生成的 HTML，避免点击后跳到 Markdown 源文；源码交付工具按既有递归规则包含新 Python 模块、README 与 SVG。

## 4. 验证结果与范围

- 桌面 **21 项自动测试通过**：原有 19 项加上抽出布局后的按钮回调、保存凭据恢复两项回归，覆盖窗口构建、回调、关闭、会话、下载与播放器失败恢复。
- 拆分后的板端代码在开发板隔离目录 `/userdata/av_dev/_structure_check_20261013/` 完成原有 **10 项单元测试**，没有占用摄像头或调用直播启停。
- 后续新增通信契约与 ROOT 路径测试，电脑上板端单元测试共 **14 项通过**。Windows 使用回环 TCP 验证相同 JSON Handler；实际产品仍使用 Linux Unix socket，没有新增 TCP 控制服务。
- Unix socket 与文件锁的新增测试尚未在 Linux 重跑：工作中 ADB 设备随后消失，板端 IP 的 SSH 端口也未连通。本轮不据此判断摄像头或板端程序故障，也没有尝试重启设备或替换服务。
- 命令入口仍接受原动作、`--config-stdin` 和 `--lines`；CLI 帮助解析通过。Controller 抽取前后 AST 完全相同，进程管理逻辑没有因文件拆分改变。
- 文档 **74 段 Bash/PowerShell 命令解析通过**，相对链接有效；源码交付包 **97 个文件**完整性检查通过。

这轮结构单测不能代替重新部署后的硬件全链路验收。开发板连接恢复后，若要使用新结构，可另安排上传与真实链路回归；当前已发布 1.1.0 免安装包继续保留。
