# 4K60 与性能监测

本版为 Windows 控制台 1.2.0。新增真实采样的性能面板、60 fps 电脑预览、CSV 和板端 VPU 硬解显示。**合成 4K60 编解码与真实相机 4K60 分开验收；当前相机驱动仍报告最高 30 fps。** 最新结果见 [验收记录](../history/4K60与性能监测验收.md)。

## 使用软件

解压本地 `releases/EVM3588CameraConsole-Windows-x64-v1.2.0.zip`，双击其中的 EXE。首次在“设备连接”输入 SSH 密码或选择自己的密钥；核对主机指纹。关闭软件只断开电脑端连接，不停止板端任务。

1. 已有直播会自动显示。进入“性能监测”，看每秒采样的指标和十分钟趋势。
2. “性能 60 fps”是电脑预览上限：完整码流先解码，再缩放到最大 1280 宽；不会改变直播或录像分辨率。源为 30 fps 时仍只显示约 30 fps。
3. “编码设置 → 填入 4K60 性能预设”填写 3840×2160、60 fps、H.265、20 Mbit/s、GOP 60。它不会直接应用。当前传感器只有 30 fps，点击应用会明确拒绝，并保留原直播。
4. 当前可用 3840×2160、30 fps、H.265、20 Mbit/s、GOP 30 验证面板；常用默认仍为 1080p30、2.5 Mbit/s。
5. “HDMI 开启”启动板端 `hevc_rkmpp`/`h264_rkmpp` 解码，RGA 缩放至不超过 1920×1080，再交给系统 ffplay 显示。分别显示解码尺寸、送给播放器的尺寸和 xrandr 实际显示模式。硬解失败会报告错误，编码和电脑推流继续运行。

CSV 在每次软件运行时自动建立于用户数据目录的 `performance/`，UTF-8 BOM，表头固定，每秒一行。面板可选新目录、导出截至当前采样的 CSV、打开目录；换目录后另起文件。保存失败保留预览，显示错误并每 30 秒重试。没有数据的字段留空，不写成零。CSV 不含密码、密钥和连接配置，不自动上传。

## 怎样读指标

| 指标 | 口径 |
| --- | --- |
| 传感器报告帧率 | 驱动报告的标称间隔，不是实测采集速度 |
| 采集 fps | NV12M 两平面校验、有效复制完成次数的增量 / FFmpeg 内单调时钟增量；最多一秒写一条统计日志 |
| 驱动序号缺口 | 有效帧之间的 V4L2 sequence 前向缺口；包括中途被驱动或校验丢弃的编号，不能单凭它认定传感器损坏 |
| 采集错帧 | NV12M 错误标记、平面数量或边界校验失败累计数 |
| 编码 fps | `-progress` 输出帧数的相邻增量 / 接收块的单调时间间隔；与累计平均 `fps` 旧字段分开 |
| 板端硬解 fps | 独立硬解进程输出计数差分；无 fps 滤镜和补帧，统计在 RGA 缩放之后，受整条输出路径的反压影响 |
| 电脑解码 fps | `showinfo@decoded` 放在 fps/缩放滤镜之前，关闭校验和，统计完整源尺寸的解码输出 |
| Qt 绘制 fps | `paintEvent` 真正绘制的新帧次数；控件重绘同一张图只算一次，不等于显示器刷新率或镜头到屏幕延迟 |
| 预览丢弃 | 原始帧拼接时丢弃旧完整帧、最新帧邮箱被替换，以及 Qt 绘制前被替换的画面；不包含有意的预览 fps 降采样 |
| 目标码率 | 配置的编码目标；不是实测流量 |
| RTSP Mbit/s | MediaMTX 路径 inboundBytes 增量；使用十进制 1 Mbit = 1,000,000 bit |
| 本订阅 Mbit/s | 当前 VideoWorker 的随机 `console` 标识对应的 RTSP 会话 outboundBytes 差分；排除 HDMI、录像和别的播放器 |
| 网口 TX / RX | 活跃有线接口中 TX 最高者，展示接口名；是整块网口的总量，包括其它业务和协议开销 |
| 链路占用 | 分别用 TX、RX 速率 / 协商速率，不把全双工两个方向相加 |
| 主机 CPU | 全部逻辑核归一化至 0–100%；进程 CPU 以一个逻辑核 100%，多线程进程可以超过 100% |
| 内存 | 进程 RSS，单位 MiB；不是总分配量或显存占用 |
| VPU 频率 | 只读取内核公开的 devfreq 节点；无节点显示不可用，不用进程 CPU 冒充 VPU 利用率 |

首次差分、进程重启、计数回退或 RTSP 会话变化时重新建立基线。板端采样超过 3 秒未更新会标记过期；视频超过 4 秒无新帧时停止展示旧帧率。恢复后的历史日志仍可查看，但不当作当前故障。低于 55 fps 的提醒仅针对源和预览上限都接近 60 fps 的场景，不把正常 30 fps 源误报成 60 fps 瓶颈。

## 源码定位

| 位置 | 职责 |
| --- | --- |
| `board/ffmpeg_pipeline/camera_control/metrics.py` | 独立采样线程、MediaMTX 会话、Linux CPU/内存/温度/网口计数及缓存 |
| `board/ffmpeg_pipeline/camera_control/decoder.py` | 私有 FFmpeg 硬解、RGA、ffplay 子进程、输出计数和错误 |
| `board/ffmpeg_pipeline/patches/0002-capture-metrics.patch` | 在已有 NV12M 兼容补丁之后增量增加有效取帧统计 |
| `desktop/evm_console/telemetry.py` | PC 后台资源采样、板端新鲜度、计数差分与 CSV |
| `desktop/evm_console/performance.py` | 有界十分钟 Qt 曲线，不依赖浏览器组件 |
| `desktop/evm_console/video.py`、`widgets.py` | 解码前缩放前计数、最新帧队列、实际新帧绘制计数 |
| `board/bsp/imx415-4k60/` | 隔离的驱动实验补丁、构建脚本与候选说明；默认部署不包含 BSP |

控制 API 保留全部旧字段和 HDMI 命令；新增 `decode-start`、`decode-stop`，与 `preview-start`、`preview-stop` 映射到同一硬解显示实现。`check.cameraCapabilities` 返回传感器枚举结果，`status.metrics` 为后台缓存，`status.boardDecode` 为解码状态。网页仍只显示手动快照，实时性能在 Qt 软件内查看。

## 更新与命令解释

以下两条在 **Windows PowerShell，av_dev 根目录**执行。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\deploy\deploy.ps1
```

解释：上传当前板端程序与补丁，不包含 BSP、内核和私人配置，不自动重启。`-NoProfile` 不加载个人 PowerShell 配置，`-ExecutionPolicy Bypass` 只影响此进程，`-File` 指定部署脚本。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\desktop\run.ps1
```

解释：用已有独立环境启动源码版 Qt 软件；脚本参数含义同上一条，路径改为桌面启动脚本。便携包用户直接双击 EXE。

以下命令在 **开发板 Bash** 执行。重建前应结束录像并按需停止直播，升级控制服务会中断其子进程。

```bash
bash /userdata/av_dev/ffmpeg_pipeline/build_capture_metrics.sh
```

解释：只对已构建的私有 FFmpeg 增量应用第二个补丁、用 4 个编译任务重建并原子替换两个私有可执行文件。保留系统 FFmpeg、厂商库和 3A 服务；修正厂商头文件搜索环境造成的重复构建问题。首次构建仍使用原 `build_runtime.sh`。

```bash
systemctl restart evm-ffmpeg-control.service
```

解释：让 systemd 重启控制服务以加载新 Python 模块，原直播和 HDMI 会停止；**不要在录像时执行**。这个命令不会升级内核或启用开机自启动。

```bash
python3 /userdata/av_dev/ffmpeg_pipeline/avctl.py start
```

解释：使用保存的配置启动一次采集硬编；必要时启动服务，不会创建两个摄像头采集器。

```bash
python3 /userdata/av_dev/ffmpeg_pipeline/avctl.py decode-start
```

解释：读取已有 RTSP，启动 VPU 硬解、RGA 和 HDMI 显示，不再次打开摄像头。`decode-stop` 仅结束这条解码显示支路。

```bash
python3 /userdata/av_dev/ffmpeg_pipeline/avctl.py status
```

解释：读取当前直播、录像、解码及性能缓存，结果为 JSON。服务停止但 socket 遗留时会返回“服务未运行”，SSH 本身仍可正常连接。

```bash
python3 /userdata/av_dev/ffmpeg_pipeline/tests/codec_4k60.py --frames 600 --output /userdata/av_dev/ffmpeg_pipeline/state/acceptance-4k60
```

解释：生成 600 帧合成 4K60 图像，硬编 MP4 后硬解并 RGA 缩放，保存计数、日志和 MPP 设备观察结果到 `--output` 目录。它不采集摄像头，输出结果不能替代真实 4K60。该测试会占用 VPU，不要与正式性能验收混在同一个统计窗口内。

内核实验的步骤、备份与回退边界见 [BSP 说明](../../board/bsp/imx415-4k60/README.md)。未做系统切换前，不能在软件里真正打开 4K60。

## 资料

- [FFmpeg 滤镜 showinfo](https://ffmpeg.org/ffmpeg-filters.html#showinfo)：解码帧计数放在预览降采样之前。
- [ffmpeg-rockchip Decoder](https://github.com/nyanmisaka/ffmpeg-rockchip/wiki/Decoder)：显式 RKMPP 硬解和 DRM PRIME。
- [MediaMTX v1.21.2 API](https://github.com/bluenviron/mediamtx/blob/v1.21.2/api/openapi.yaml)：使用会话 query、id、inboundBytes、outboundBytes，不累计所有订阅者冒充本机带宽。
