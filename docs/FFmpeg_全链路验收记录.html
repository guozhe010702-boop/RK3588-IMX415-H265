FFmpeg + RK3588 VPU 全链路验收记录

测试日期：2026-10-13，EVM3588-B / Ubuntu 20.04.5 / BSP 5.10.110 / IMX415 con7。采集节点 /dev/video44，1080p NV12M 两平面，H.265 CBR 2.5 Mbit/s、30 fps、GOP 30，无音频。

1. 硬编与图像链路

独立 FFmpeg 已在板端原生编译完成，hevc_rkmpp 与 h264_rkmpp 编码器可查到。本轮使用 hevc_rkmpp，编码进程实际打开 /dev/mpp_service，日志显示 rkmpp 硬件编码；没有软件编码回退。

离线测试图 640×360 / 60 帧，生成 HEVC MP4，ffprobe 实际解码计数通过。真实摄像头为 1920×1080，Y/UV stride 均为 1920，平面有效大小分别为 2073600 / 1036800 字节。两端正常颜色和持续更新的画面由用户确认。

本轮硬件确认针对编码端。HDMI 使用保留的系统 ffplay；其日志有 SDL 硬件渲染初始化失败与颜色转换回退信息，画面实际正常。因此本轮不宣称 HDMI 硬件解码或零拷贝显示已完成，可在下一阶段单独优化。

NV12M 拷贝测试覆盖两平面索引、不同 padded stride、非零 data_offset、短平面、异常边界与奇数尺寸拒绝；板端 gcc -Werror 测试通过。控制层六项单元测试通过，包括配置校验、摄像头占用拒绝、录像中拒绝参数切换、流未就绪时拒绝截图，以及低磁盘空间拒绝新录像、结束录像保留采集。低磁盘测试使用模拟值，未填满实际开发板磁盘。

停止录像没有结束直播，录像文件为流复制封装 MP4，没有第二次编码。RTSP 服务重启测试发生在手动录像完成后；跨故障的录像连续性不在本轮已验证范围。

首次中途加入 HEVC 直播时，播放器可能在下一个 IDR 前短暂打印缺少参考帧信息；上述客户端能在一秒左右出画面。记录的是连接到可解码帧的等待时间，不是镜头到显示器的端到端延迟。端到端延迟尚需拍摄时钟或 LED 的专门测试。

板端测试从 09:53:24 至 10:23:24（北京时间），持续 1800.11 秒，共 353 次状态采样，整体验收脚本退出码为 0。

指标 实际结果

采集进程 PID 始终不变，没有重启或超过阈值的帧停滞
VPU / HDMI 所有样本均确认 VPU 设备打开、HDMI 播放进程在运行
编码 CPU 单核占用 5.08%～7.61%；统计对象是采集编码进程，不是整板全部进程

5 秒查询与 FFmpeg 一秒进度更新存在采样边界差异，单次差分帧率 29.027～35.276 不代表相机真的在这些瞬时帧率间切换。整体帧推进与电脑连续解码用于判断平均运行帧率。

电脑 FFmpeg 独立持续解码 30 分钟，正常退出码 0；解码 53989 帧，媒体时间 00:30:00.000，最终统计 fps=30.00、speed=1x、dup=0、drop=0。板端 HDMI、电脑可见 ffplay 窗口及该独立解码进程在测试期间同时读取 RTSP。结束验收后保留 HDMI 与电脑可见窗口，不继续运行额外的解码测试进程。

4. 部署隔离与交付

新组件位于 /userdata/av_dev/ffmpeg_pipeline/，私有 MPP/RGA 仅由新 FFmpeg 使用。系统 FFmpeg、原厂库和 RKAIQ/ISP 服务保留。两个新 systemd 服务运行但未启用开机自启动。重复源码部署不停止或重建当前链路；部署后仍为同一采集进程。

源码版本、补丁、构建脚本与配置可复现；versions.json 固定上游提交与 MediaMTX 下载校验值。构建产物 SHA256 在板端 runtime/build-manifest.json，公开构建摘要见 FFmpeg_构建锁定记录.json。原方案本地备份目录为 backups/before_ffmpeg_fullchain_20261013_093100/。

录像、截图、进程快照和测试原始日志保留本地，不上传 GitHub。公开文档只记录必要测试指标。
