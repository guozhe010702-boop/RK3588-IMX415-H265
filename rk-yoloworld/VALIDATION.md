## 上一阶段已验证的基础链路

- 用户提供的部署目录含 129,536,946 字节 CLIP、15,327,930 字节 YOLO-World 模型、80 类文本和示例 bus.jpg。SHA-256 保存在本地部署包 `package-manifest.json`。
- 私有 RKNN runtime **2.3.2 (429f97ae6b@2025-04-09)**、当前 NPU 驱动 **0.8.2**：真实模型初始化与推理成功，未升级驱动/内核。
- CLIP 输入 `[1,20] INT64`，输出 `[1,512]`；YOLO 图像 `[1,640,640,3]`，文本 `[1,80,512]`，6 个 INT8 NCHW 检测头。
- 9 个独立 context 绑核成功，日志记录 worker/core/mask/context。相同 bus 图片的单 context 与 9 context 顺序、**9 context 同时并发**推理均得到相同的 **5 个框**：4 个 person、1 个 bus。改为仅有 bus 一类后，得到 **1 个 bus 框**，填充类别未泄漏。
- 请求并实际分配 **3 个 mmap 缓冲**；实际采集格式 **2560×1440 NM12、双平面、两个 stride 均为 2560**；视频节点 S_PARM 不支持，传感器子设备报告 **60 fps**。
- 板端 `/proc` 核对检测进程仅持有 `/dev/video44`，FFmpeg 持有 `/dev/mpp_service`；两个进程各自加载其私有 RGA 库。一次采样实际检测进程任务数为 **16**，不把 FFmpeg 内部线程算入。
- 用户已确认 Windows 实时画面和目标框正常；离线抽帧也检查了原帧与框的位置及颜色。
- 上一阶段单路优化版网络负载 8.024 秒采样：**15.896 Mbit/s MPEG-TS UDP payload**。这是该采样期间的实测值，不等同于 40 Mbit/s 编码目标，也不包含 Ethernet/IP/UDP 首部。
- 取上一阶段单路版实际推流中完整关键帧片段：**2560×1440 H.264、无 B 帧、108 帧、PTS 严格递增，按 PTS 测得 23.008 fps，完整片段解码错误 0**。原始抓包从 GOP 中间开始，截取完整关键帧片段前的缺 PPS 提示不作为完整片段错误。

## 发现并修正的问题

1. 包内 CLIP 的 token 类型实际是 INT64，已按查询结果适配，不再写死 INT32。
2. 私有 RGA 的 im2d API 是 **1.10.4**，Meson 库发行文件名是 **2.1.0**；包内原 RGA 是 API **1.10.1**。不能只按库文件名判断 API 版本。
3. 纯色检查发现 full CSC 的 YUV→YUV 路径虽然返回成功，却没有执行所需矩阵变换。最终采用 RGA 缩放、模型尺寸 CPU 范围映射、RGA BT709-limited→RGB；饱和色测试通过。为此重新进行修正版长测，旧预处理版本的约 24 分钟运行不代替最终验收。
4. BSP 工具链构建的用户态库要求 GLIBC 2.33，当前板为 2.31；改用 Ubuntu 20.04 AArch64 GCC 9.4 用户态工具链。
5. 正常停止时取消一半 rawvideo/NUT 包会损坏最后一帧；改为写完已开始的包再退出，真正堵塞仍有每包 2 秒超时。
6. 默认 1/60 编码时基曾产生一次 DTS 舍入重复；显式设置微秒编码时基，重新进行完整长测，旧的 5 分钟试验不充作通过结果。
7. 原控制器停止后会恢复 AIQ RAW 普通调度；测试包装器现在继承此前已经启用的 4K60 传感器 RAW 调度，使用独立日志并在结束时恢复。单独提升检测采集线程优先级并没有改善此板表现，默认保持 0。
8. ISP 启动的前几帧可能带上一轮的旧时间戳/序号，已丢弃前 5 个有效帧；启动跳变单独记账。运行阶段缺口继续保留，不用清零掩盖。
9. 早期失败的 CMake 配置遗留空的 Release 优化选项，曾导致后续构建未启用优化。构建脚本现明确设置并检查 `-O3 -DNDEBUG`，CPU 从约 3.3 核降至约 2 核，模型启动耗时缩短；最终长测仅采用修正后的优化二进制。

主机 ASan/UBSan 的三个测试通过。GCC 9 容器环境使用非 PIE 测试程序避免其信号处理启动故障；LeakSanitizer 未启用，不声称通过泄漏检测。生产程序没有采用这些测试专用选项。

## 实测边界

9 个推理任务会乱序完成，为保证框和原图相配且输出不倒序，旧结果按约定被丢弃。**推理 FPS 与有效输出 FPS 是两个不同指标**。帧龄为采集时间到管道写完，不是镜头到屏幕延迟。运行阶段的驱动序号缺口尚未消除，约占本次有效帧与缺口合计的 1.25%；其根因仍需 BSP/ISP 专项分析。

实际视频和原始 JSONL/CSV、设备快照只留在本地 `logs/` / `build/`，不进入 Git。真实并发图片校验和最终 30 分钟结果见上文。
